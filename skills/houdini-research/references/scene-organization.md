# AI 可检索的场景组织

按需阅读 [建模](scene-modeling.md)、[机械](scene-mechanics.md)、[特效](scene-fx.md) 或 [镜头](scene-shots.md)。本约定用于组织资产和定位工作范围，详细节点经验仍由 `knowledge` 检索。

## 先确定当前场景

先用 `window_session` 核对窗口、工程和未保存状态。磁盘检查标记 `scope=disk_only`，用 HIP 校验和绑定结果。可见窗口检查标记 `scope=live`，记录会话、帧和快照。磁盘文件相同也可能有未保存修改，重用摘要前回读目标。

按项目摘要、资产、部件、接口逐层展开。先用 `graph_read(depth=1,limit=5)` 查当前层，按返回的 `next_offset` 翻页。选中目标后才检查内部网络，明确见证输出后才 `cook` 或取画面。一次读取的页数和深度按任务决定。显示代理、几何加载和计算成本分别核查。

## 语义层级与真实路径

逻辑目录表达用途，例如工地 → 塔吊 → 塔身 → 标准节 → 接头。索引保留实际节点路径，逻辑父子与 Houdini 变换父子分别记录。已有工程可把这一目录放在 HIP 旁的 `AI-scene-index`，保留当前结构和表达式。

新资产在有用的边界封装，提供清楚的控制入口和输出。`CTRL`、`IN_*`、`OUT_*` 可作为新建节点的命名约定。旧网络沿用读到的真实名称。仅为整理目录而移动有引用、动画或父级变换的节点，需要结构迁移方案及验证。

## 最少记录什么

根摘要使用 `schema_version`、场景记录 ID、来源、统计和分片入口。每个入口只给名称、用途、节点路径和对应索引文件。分片按资产或任务拆分，路由表只列 ID、名称、路径和详情文件，参数、关系与测量放单件详情。先读目录，再按 ID 取需要的对象，避免一个分片又装入整组节点的全部参数。

| 内容 | 记录方式 |
|---|---|
| 来源与时效 | HIP 路径及 SHA256、观察时间、Houdini 版本、disk_only/live、帧。live 另记会话 ID 和图快照范围。 |
| 身份 | `id` 为持久登记的对象 ID，`path` 为当前定位地址，`identity_status` 说明原生或旁车身份是否确认。 |
| 名称与用途 | 显示名称、别名、角色和它们的来源。名称推断标记为 inferred，人工命名标记为 declared。 |
| 控制与接口 | 真实参数或节点路径、单位、有效范围及其来源、输出和接点定义。尚未暴露的控制入口记为缺口。 |
| 关系 | independent/reference/instance/unknown、母件或源路径、已确认的依赖、覆盖状态 complete/partial/unknown，另记 coverage_scope 的根路径与已核查引用类型。 |
| 测量 | 帧、单位及依据、local/world 坐标系、包围盒及其测量来源。尚未计算的项留空。 |
| 证据与未知 | 已知问题、实验或配方 ID，以及仍待确认的身份、关系和尺度。 |

只有实际需要独立定位或修改的资产边界才登记 ID。旁车首次登记生成 UUID，后续保留。改名时将同一对象的新路径写回原记录，复制出独立对象时生成新 ID 并记来源，每个放置实例也有自己的 ID、另关联母件 ID。复制节点可能连同 userData 一起复制，因此登记前检查重复 ID。无法证明身份连续时标记 ambiguous 或 unresolved，并重新核对对象。

当前 `graph_read` 能读路径、类型、接线和非默认参数，稳定 ID、完整实例关系和场景单位尚需额外证据。旁车 ID 表示已登记记录，工具对改名后的自动重定位能力要单独验收。

## 修改之前与之后

修改前写清目标和预期影响，例如一处放置、母件的全部引用、一个镜头。对关系不全的对象，分别列已确认的影响和未核查范围。根据用户的目标补查关键依赖，使用 `expect` 核对旧值，给 `graph_edit` 的批次命名。

修改后回读目标与有关依赖，比较快照并检查所需几何或画面，更新受影响分片。保存之前的记录版本及回退来源。参数引用、Object Merge、HDA 定义、外部文件、实例和镜头覆盖分别是不同的依赖证据。

索引核对来源版本、目标路径和引用。HIP、外部 HDA、USD 或缓存变更后，相关摘要标记 stale 并重新测量。手调后的 live 摘要也要回读目标控制和依赖，未保存标志持续为 true 不能证明期间内容一致。完整依赖尚未检查时，只声明已核查范围。翻完一层仅确认该层枚举完整，未登记对象还需查实是否存在。缺失文件、重复 ID、错误路径和单位不明都应在摘要中可见。

长度须有尺度依据，角度注明 degrees/radians，动画记录 FPS 和时间范围。`cook` 返回的是局部包围盒。需要世界尺寸时还要核对完整变换，单位未知时保留场景单位，先核查尺度再作物理换算。

## 按规模逐步验证

首个工程验证能否从语义入口找到真实路径、定位一次局部操作，以及指出共享源的已知使用者。随后在工程副本验证改名和复制、母件修改、手调后的索引失效。超大场景的加载时间、内存和局部更新耗时需要真实规模测试。

Solaris/USD 的层、引用、payload 和实例可以承载更大场景。接入时保留相同的身份和来源规则，另外记录 prim 路径、层、资产版本和加载状态，并验证层覆盖与实例编辑范围。[SideFX 场景组合说明](https://www.sidefx.com/docs/houdini/solaris/usd.html)

遇到当前工具读不到的关键关系或无法可靠写入的元数据，按 [缺口评审](gap-review.md) 记录复现与验收。用局部实测修订本规范，新增结论注明适用工程和验证条件。
