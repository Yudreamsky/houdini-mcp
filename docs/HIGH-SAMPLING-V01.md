# 高预算采样诊断 v01

2026-09-22，用户要求用“溢出饱和式”参数尝试解决预览噪点。本实验只改变采样预算，保持 C3 法兰特写的机位、960×640 分辨率、GI1、灯光A、五套材质、几何、曝光与 Alpha 正确处理的 OCIO 链。

## 参数与真实执行入口

| 项目 | 原 MCP 预览实际值 | 本次候选 |
|---|---:|---:|
| Pixel Samples | 2×2 | 9×9 |
| Min Ray Samples | 1 | 4 |
| Max Ray Samples | 9 | 64 |
| Noise Level | 0.01 | 0.002 |
| 漫反射反弹上限 | 1 | 1 |
| 降噪 | 无 | 无 |
| Mantra CPU 线程设置 | 8 | 0，即全部32个逻辑核心 |

像素主采样数为原来的20.25倍。按单个BSDF的参数乘积计算，次级采样下限预算为81倍、上限预算为144倍；这不是实际光线计数或速度倍率。采样参数会相乘，噪声阈值决定自适应是否继续加样。[SideFX采样说明](https://www.sidefx.com/docs/houdini/render/sampling_tab.html)。在线文档为22版本，本次另以本机20.5.487导出的IFD验证关键数值。

原始HIP保存的是3×3，但上一轮MCP preview任务实际覆盖为2×2。当前MCP final也固定覆盖为4×4，不支持传入任意采样网格。因此这次通过独立原生hython运行Mantra，明确不是MCP高采样接口验收，也没有修改服务配置或接口。

候选保存重开后回读参数，并检查导出的IFD实际含 `image samples 9 9`、`minraysamples 4`、`maxraysamples 64`、`variance 0.002`、`diffuselimit 1`。GUI中的地图工程未参与渲染。

## 结果与证据

已完成完整960×640 C3图，原生Mantra渲染调用2622.50秒（约43分42秒，含IFD导出/启动），没有降噪。源HIP、HDA、218件、相机/灯/材质和OCIO/Alpha节点参数保持；最终保存重开与输出指纹通过。GUI地图仍为第97帧、无未保存修改。本地交付入口为 `assets/high-sampling-v01/README.md`。

实际看图：密集颗粒明显消退，立柱金属平面、法兰面和背景红管更干净；蓝垫间隙、螺栓与倒角仍可读。黑管的大块浅灰反光仍存在，采样没有解决灯光/材质的层次问题。本轮只完成C3高采样图，C1/C2仍是此前预览。

| 预先固定的平滑区域 | 原图高频幅度/255 | 高采样幅度/255 | 幅度下降 |
|---|---:|---:|---:|
| 管身 | 0.6490 | 0.1287 | 80.2% |
| 蓝垫 | 0.5616 | 0.1287 | 77.1% |
| 立柱平面 | 12.2559 | 1.3186 | 89.2% |

这些是显示PNG局部二阶差分的稳健幅度，不是全图信噪比；极低幅度区受8位量化影响。结合原图目视，支持“噪点显著收敛”，不支持“零噪点”或“最优采样”。没有通过模糊、降噪或改变材质来消除颗粒。

- `baseline.json`：原MCP请求的真实采样值、8线程、105.85秒和最终对照PNG指纹。
- `status.json` / `render-high.log`：候选参数、实际Mantra输出、进度、耗时及终态。
- `ifd-sampling-proof.json`：导出到渲染器的参数证据。
- `process-owner.json`：本次独立hython与Mantra的进程身份，方便恢复时避免重复提交。
- `noise-comparison.json`：渲染前固定的三个平滑区域，用二阶差分的稳健幅度比较显示空间高频波动。它只是噪点代理指标，不能当作无偏路径追踪误差、完整收敛证明或AOV分离。
- `final-reopen.json` / `visual-review.json`：保存重开、源资产继承与最终目视结论；`session-before.json` / `session-after.json`核对GUI未受影响。

原始EXR和无降噪PNG均保留。因线程数不同，实际耗时可作为此次工作的成本记录，不能据此推断同机同线程的采样倍率或GPU加速比。

## 发现的最小MCP缺口

后续候选是为现有render_frames增加显式Mantra采样参数，验证像素网格、最少/最多光线和噪声阈值，保存到不可变任务请求并在worker设置后回读。明确自定义参数与preview/final的优先级，续渲不能改变参数；不要静默覆盖。此处是提案，本轮没有实施MCP或Skill升级。

常用档应在高预算结果验收后通过小范围收敛试验确定，不因“更高”就全项目设为默认。当前仍为Mantra CPU；本资产Karma XPU材质迁移尚未验收。
