# 0.17：双层总装的最小资产化

原先风管及前后横担依赖固定场景路径，修改层高虽已联动，却不能独立复制整段总装。本轮将已验收的218件封入 `workai::two_tier_snapshot::1.0.*`，只开放 `tier_y`。两段风管、两个上横担共4件移动，其余214件固定。默认550mm，范围450–800mm；所有尺寸是照片指导下的估计，不是设计规格。

这是带一个参数的**快照HDA**，其他尺寸没有重新生成。22个MCP工具、10个既有生成配方保持；快照不加入 `list_procedural_assets` 或 `upsert_asset_instance`。实例由交付HIP或安装对应HDA创建，后续使用现有 schema、set、inspect、preview、save/open 工具。

## 修改与回退

`asset_ops.set_parameters` 仅对这个锁定类型增加检查前状态、写入、cook、验收及失败复位。普通节点的数值写入语义保持。检查实际构件身份、顶点移动、连接、法线、颜色和面材质；两站共40个底板承托样本及四处丁字端接检查。异常身份、固定件移动、端接或承托失败都不能作为成功结果返回。

严格参数边界在Houdini里可能自动夹取值；MCP仍在写入前拒绝越界请求，避免默默接受另一个数值。动画/表达式通道与解锁HDA拒绝按此协议更新。失败复位若无法核验会明确报错，不将错误吞掉当作成功。

## 几何和外观继承

HDA内嵌静态网格、依赖清单与PythonModule，运行只需hou和标准库。源对象单位矩阵先核验；原场景保留在前版HIP中。原218件形体/法线/颜色保留；186件原先依赖对象材质（其中6件完全没有面材质属性），封装时显式写入相同的有效面材质。不能把这次属性迁移描述为所有原始属性逐字节不变。

材质网络仍在配套HIP中。独立安装HDA可生成几何，但它还不是携带完整外观依赖的资产包。这是下一轮材质管理的具体缺口。

## 照片视角与下一轮

建立照片侧仰视及反向仰视，先观察管线顺序、两站框架和风管遮挡。未解算原照片相机；较清楚的反向图不代表与照片同向。首次图太暗且取景过远，补光后结构较可读，但镀锌件高光仍偏亮，当前定位是检查图。

下一轮建议按实际问题推进：

两位子代理已完成官方资料调研，合并的[产品外观研究与最小实验](PRODUCT-LOOKDEV-RESEARCH.md)区分了资料支持与本机待验事项。

1. 材质继承/空绑定/丢失节点与外部贴图检查，先让HIP和HDA外观交付边界明确。
2. 可复用检查灯光，针对仰视、法兰近景、总装分别保存可恢复设置，优先解决暗面与高光溢出。
3. 固定机位与材质版本，比较预览和成图的噪声、时间及可读性；不据显卡可用就宣称XPU加速效果。

Skill保存经测试的步骤、适用范围和失败案例；算法及参数写入放在代码中，不把每个SOP增加为新工具。暂不扩展通用灯光系统、材质库或渲染器适配范围。
