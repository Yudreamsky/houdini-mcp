# 首轮摄影机、间接照明与单灯比较

2026-09-22，本机 Houdini 20.5.487。运行版仍为 0.17.0，MCP 接口和 Skill 未修改。七张原生 Mantra PBR 预览通过外部 MCP SDK stdio 调用；最后用已有 EXR 在 Houdini 原生 COP2 中修正透明边缘并重新合成，没有追加 Mantra 帧。

## 结论

- 总装 C1、照片侧仰视 C2、隔振法兰特写 C3 已保存并实际出图，采用透视相机、36mm 水平孔径，焦距分别 65/75/100mm。关闭景深及运动模糊。
- 固定 C1 比较 Diffuse Limit 0/1/2，暂选 1。最终 PNG 前景平均差：0→1 为 0.743/255，1→2 为 0.0542/255。低采样结果支持本轮取舍，不能代替高采样收敛判断，也不是室内 GI 通用结论。
- 保留原补光 A 为后续基准。B 只把 photo_underfill 移到照片侧并转向目标；面积仍 4×4m、强度仍 4。B 主要提亮红管和风管，黑管、法兰改善有限，C1 风管侧面层次减弱。因此没有将“更亮”判为更好。
- 五套材质、218 件几何保持。黑管特写出现过宽浅灰反光、金属高光散且有噪点，仍待独立三面光候选及材质小样，未宣称达到最终产品图。

## 色彩链实测

旧 source→OUT 图形没有显示转换。原生灰阶测试：线性 0.18 保存 PNG 得 46/255；1、4、16 都截到 255，说明旧导出不能直接用来判断 HDR 高光是否已经丢失。

本轮在 COP2 VOP 内采用 `ocio_transformview`：传统 Mantra 场景按 Linear Rec.709 (sRGB) 解释 → sRGB - Display / ACES 1.0 - SDR Video。保留线性 EXR，曝光不变。使用本机随 Houdini 安装的 ACES 1.3 / OCIO 配置，配置路径与 SHA256 记录在资产清单。这个工作空间约定并不等于照片色彩标定。

对预乘 Alpha 的 EXR，先除 Alpha，再做非线性显示变换，再乘回 Alpha；PNG 编码写直通 Alpha。0.18/1/4 三档、Alpha 0/.25/1 共九个色块验证：非透明 RGB 分别约 91/207/244，Alpha 不同而直通 RGB 相同；零 Alpha 保持零。避免把非线性变换直接施加于预乘颜色造成亮边。

最终七张 PNG 来自原生 COP2 重合成；原 MCP 任务输出与修正前文件保留作历史，原始 EXR 的 SHA 不变。最终应以 `composite-report.json` 和资产 `manifest.json` 为准，不能把旧任务 PNG 的 SHA 当作新合成的 SHA。

## 验证与证据

本地交付入口：`assets/lookdev-trial-v01/README.md`；主工程 `candidate-01/C1-GI1-A.hip`。资产和现场照片不推 GitHub。

本地证据目录 `evidence/lookdev-trial-v01/`：

- `render-report.json`：七个 MCP 任务、EXR、分辨率、耗时、GUI 恢复记录。
- `color-patches.json` / `alpha-patches.json`：真实 PNG 编码值及原生浮点色块核验。

- `composite-report.json`：每份最终 HIP/PNG/原 EXR 指纹及来源任务。

只改变一盏灯的六个姿态参数，其他灯参数全量比对。先前设计列了八个直接/环境灯；这次完整检查另发现一个 legacy ambient 节点，共九个灯节点参数原样保留。不能用有限灯类型枚举替代完整灯光盘点。

## 下一次最小升级方向

MCP 的优先缺口是现有预检回读完整相机、灯节点、实际材质、ROP 引擎/反弹、OCIO/Alpha 合成链及依赖指纹。能成功保存 PNG 不代表显示转换正确。先增加只读诊断，再考虑受控应用单灯姿态及复位；没有必要按每个节点增加工具。

Skill 待整理的实测经验：灰阶/HDR/半透明色块先验；工作空间与显示变换分开记录；单变量 A/B 不以亮度判优；开敞样段增加反弹收益有限；原始 EXR 与最终显示 PNG 的证据分别保留。本轮仅记录报告，尚未修改稳定 Skill。

下一张外观候选应独立替换为长面主光、低位补光、窄条轮廓光，逐盏检查贡献，优先收窄黑管反光和控制法兰倒角高光。Karma XPU 材质迁移、AOV 与最终采样另验，不与这次对比混在一起。
